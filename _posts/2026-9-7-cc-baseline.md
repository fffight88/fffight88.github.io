머신이 바뀌어도 동일한 AI 코딩 환경을 재현하기 위한 Claude Code 하네스 번들 인스톨러의 핵심 설계를 정리한 문서입니다. 에이전트 파이프라인 설계, 정적 리뷰가 놓치는 런타임 결함 게이트, 사용자 설정을 보존하는 비파괴 병합 전략, 보안 스캔 자동화를 다룹니다.

---

### 5-에이전트 QA 파이프라인 설계

#### 핵심 성과
- ___플랫 팬아웃이던 에이전트 호출을 단계별 시퀀스로 재설계하여 반쯤 완성된 코드가 리뷰되는 문제 제거___
- ___중복제거 매트릭스로 게이트별 소유권을 명시, 에이전트끼리 같은 검사를 반복하지 않도록 정리___
- ___모든 이슈에 decision_type을 부여해 자동 수정과 사용자 판단이 필요한 항목을 구조적으로 분리___

#### 파이프라인 구조

```
/plan  (Meta: Security Impact / Code Quality Impact / UI Impact)
   │
   ▼
DIRECTION  (그린필드 전용 — 디자인 프로파일/시스템이 있으면 생략)
   └─ design-director   레인 분류 → 후보 3개 → 사용자 인터뷰 → 방향 확정
   │
   ▼
EXECUTION
   ├─ [UI]      → publisher    프로파일 → 재사용 우선 작성 → 토큰/상태/a11y 자체점검 → 렌더 비교 + axe 검증
   └─ [로직]    → 오케스트레이터가 데이터·이벤트 결선
   │
   ▼
AUDIT GATES  (병렬 — 단일 메시지로 동시 호출)
   ├─ security-auditor   (Security Impact: Yes/Unknown)
   └─ code-reviewer      (Code Quality Impact: Yes/Unknown)
       └─ 각각 최대 3회 루프 → 둘 다 끝나면 HTML 리포트 1회 생성
   │
   ▼
e2e-tester   (기능 상호작용만 — 시각·a11y는 publisher가 이미 담당)
```

UI가 없는 계획(`UI Impact: No`)이면 design-director와 publisher가 모두 생략되고 `구현 → (security-auditor ∥ code-reviewer) → e2e-tester`로 되돌아갑니다.

#### 중복제거 매트릭스

에이전트가 늘어날수록 같은 검사를 여러 곳에서 반복하는 낭비가 생깁니다. 각 관심사의 **소유자를 하나로 못박고**, 나머지 에이전트는 그 항목을 건드리지 않도록 규칙화했습니다.

| 관심사 | 소유자 | 나머지가 하지 말아야 할 것 |
|---|---|---|
| 제품의 시각적 방향 (1회 결정) | design-director | publisher가 화면마다 방향을 재결정하지 않음 |
| 디자인 토큰·클래스 네이밍 준수 | publisher | code-reviewer는 CSS 네이밍 지적 생략 |
| UI 상태 커버리지 (empty/loading/error) | publisher | — |
| 런타임 a11y (axe-core) | publisher | code-reviewer / e2e-tester는 a11y 생략 |
| 로직 오류, 엣지 케이스, 컨벤션, 데드코드 | code-reviewer | — |
| XSS / innerHTML / 인라인 시크릿 / 의존성 취약점 | security-auditor | — |
| 기능 상호작용 (클릭→결과, 네비게이션, 폼 제출) | e2e-tester | publisher는 상호작용을 테스트하지 않음 |
| 런타임 불변식 + 데드 컨트롤 스윕 | e2e-tester | 정적 리뷰는 구조적으로 불가 |
| 시각 베이스라인 드리프트 | publisher | 정적 리뷰는 구조적으로 불가 |

#### decision_type 분리

리포트의 모든 이슈에 후속 조치 유형을 부여해, 오케스트레이터가 "고칠 것"과 "물어볼 것"을 판단할 수 있게 했습니다.

| decision_type | 후속 조치 |
|---|---|
| `auto` | 오케스트레이터가 코드를 수정하고 재감사 요청 |
| `design` | 사용자 인터뷰 후 설계 변경 |
| `business` | 사용자 인터뷰 후 정책 결정 |

`design` / `business` 이슈가 1건 이상이면 인터뷰 직전에 데스크톱 알림을 발송합니다 — 감사 루프가 길어지면 사용자가 터미널을 보고 있지 않기 때문입니다.

#### 사용 기술
- Claude Code Subagent, 마크다운 기반 에이전트 정의, 구조화 JSON 리포트 규약

### 런타임 결함 게이트 설계

#### 핵심 성과
- ___네 개 에이전트를 모두 통과하고 최종 육안 검수에서야 잡히던 결함군을 게이트로 승격___
- ___"시나리오가 끝까지 돌았다"를 PASS로 인정하지 않도록 합격 기준 자체를 재정의___
- ___클릭 가능한 요소 전수 스윕을 에이전트 내장 프로토콜로 만들어 매니저가 매번 작성하지 않도록 자동화___

#### 문제 인식

정적 소스 리뷰(security-auditor, code-reviewer)는 **실행하지 않으므로** 다음 결함군을 구조적으로 탐지할 수 없습니다.

- 클릭 시 화이트라벨 에러 페이지 / 500 응답
- 미바인딩 이벤트 핸들러 → `ReferenceError` (버튼이 아무 반응도 하지 않음)
- 시각 베이스라인 드리프트, 원본값 노출·중복 표기

E2E 시나리오도 해피패스만 따라가면 이를 놓칩니다. 시나리오는 "흐름이 끝까지 돌았다"를 검증할 뿐, "모든 요소가 제 효과를 냈다"를 검증하지 않기 때문입니다.

#### 필수 사전검사 (Pre-pass)

시나리오와 **별개의 필수 게이트**로, 모든 화면에서 실행됩니다.

```
(A) 런타임 불변식 — 모든 화면전환·클릭 직후 단언
    · 화이트라벨/에러 페이지 없음, URL이 /error로 빠지지 않음
    · HTTP 상태 4xx·5xx 아님 (XHR / fetch / 네비게이션 전부)
    · 콘솔 에러 0건 — ReferenceError / is not defined 는
      미바인딩 핸들러의 결정적 시그니처
    · 예외 허용은 명시적 allowlist(예: favicon 404)만

(B) 데드 컨트롤 스윕 — 클릭 가능한 요소 전수 열거 후 하나씩 활성화
    · 대상: button, a[href], [onclick], [role=button], 탭·팝업 트리거
    · 클릭 후 관측 가능한 효과 1개 필수
      (네비게이션 / 팝업 / 네트워크 요청 / DOM 변경 / 다이얼로그)
    · 아무 효과 없음 또는 ReferenceError → FAIL
    · 팝업은 실제로 열어서 (A) 불변식을 팝업에도 적용
    · 삭제·로그아웃·결제 등 파괴적 컨트롤은 자동 제외 후
      skipped-destructive 로 보고

(C) PASS 재정의
    화면 PASS = 시나리오 완주 ∧ (A) 불변식 유지 ∧ (B) 스윕 클린
```

#### 증거 원칙

체크리스트의 `✓` 표시만으로는 통과로 인정하지 않습니다. 각 항목을 **실행 가능한 단언**(셀렉터/액션 + 기대값)으로 변환해 실제로 실행하고, **관측된 실제 값**을 증거로 남기도록 규정했습니다.

#### 사용 기술
- Playwright MCP (5개 서버 병렬), 브라우저 콘솔·네트워크 수집, 실패 시 `e2e-results/fail-{N}-{timestamp}.md` 아티팩트 자동 생성

### 비파괴 병합 & 자가 진단

#### 핵심 성과
- ___사용자의 기존 ~/.claude 설정을 한 줄도 덮어쓰지 않는 병합 전략 수립___
- ___훅이 23회 중복 등록된 실사용 사례를 발견하고 병합 알고리즘의 근본 결함을 수정___
- ___--doctor 자가진단에 중복 등록 경고를 추가하여 같은 결함이 조용히 재발하지 않도록 차단___

#### 파일 유형별 병합 전략

설치 대상이 사용자가 직접 손대는 설정 파일이므로, 유형별로 다른 병합 방식을 적용합니다.

| 대상 | 방식 | 보존 대상 |
|---|---|---|
| `CLAUDE.md`, `MEMORY.md` | 마커블록 치환 (`<!-- BEGIN cc-baseline -->` ~ `<!-- END -->`) | 마커 밖의 사용자 작성분 전부 |
| `settings.json` (hooks) | `_ccBaselineId` 기준 중복 수렴 병합 | 같은 이벤트의 사용자 훅 |
| `.claude.json` / `.mcp.json` | mcpServers 키 단위 병합 | 사용자가 등록한 다른 MCP 서버 |

마커블록이 없으면 파일 끝에 추가하고, 있으면 그 구간만 치환합니다. 설치 전 타임스탬프 백업을 남기며 `--dry-run`으로 변경 예정 내역만 미리 확인할 수 있습니다.

#### 훅 23회 중복 등록 사건

한 설치 환경에서 세션종료 정리 훅이 **23개** 등록되어 세션이 끝날 때마다 23번 실행되고 있었습니다. `--doctor`는 "훅 정상 등록됨"으로 보고하고 있어 더 오래 발견되지 않았습니다.

원인은 두 가지가 겹친 것이었습니다.

```
[원인 1] 병합 로직이 첫 항목만 교체하고 멈춤
  mergeHooks()는 _ccBaselineId가 일치하는 첫 엔트리를 교체한 뒤 종료
  → ID 태깅 이전에 설치된 사본들은 영영 수렴되지 않고 누적

[원인 2] 매칭 키가 i18n 변경으로 깨짐
  설치된 훅과의 매칭 키가 statusMessage 문자열
  → 영문화(fad22c6) 이전 설치본은 한국어 문자열을 보유
  → harnessIdOf()가 외부 훅으로 오판 → 교체 대신 매번 추가
```

수정 내용:

- 첫 항목 교체 후 **남은 동일 ID 사본을 전량 수렴**하고, 비워진 엔트리는 정리 (같은 이벤트의 사용자 훅은 무손실)
- 영문화 이전의 한국어 `statusMessage` 3종을 매핑 테이블에 등재하고, "배포된 statusMessage 값은 반드시 목록에 유지"를 주석으로 명문화
- `--doctor`가 존재 여부가 아닌 **등록 횟수**를 세어 2회 이상이면 경고

#### 설치 전 충돌 감지

병합으로 해결되지 않는 충돌(사용자 훅과의 동작 간섭)은 설치 전에 경고합니다.

| 규칙 | 감지 대상 | 사유 |
|---|---|---|
| 1 | `SessionStart`에 비하네스 훅 존재 | 컨텍스트 주입이 동시 실행되어 지시가 충돌할 수 있음 |
| 2 | `PreToolUse` matcher가 `.*` 또는 playwright-test와 겹침 | E2E 가이드 주입 훅과 이중 발화하거나 MCP 호출을 차단할 수 있음 |

#### 경로 정책 훅

`Write`/`Edit` 시도마다 순서대로 적용되며, 두 검사 모두 `realpath()`로 경로를 정규화해 심볼릭 링크·`../` 우회를 차단합니다.

- **차단:** `~/.claude/memory/`는 cc-baseline 관리 영역이므로 직접 쓰기를 막고 프로젝트별 메모리 경로로 유도
- **자동 승인:** `/.cc-audits/` 하위는 감사 리포트 저장 위치이므로 승인 프롬프트 없이 통과

#### 사용 기술
- Node.js 내장 모듈 only (외부 의존성 0), 마커블록 파서(코드펜스 인식), 타임스탬프 백업, `--dry-run` / `--doctor` / `--uninstall --purge`

### 보안 스캔 & 감사 리포트 자동화

#### 핵심 성과
- ___스캐너 미설치를 조용한 스킵이 아닌 명시적 이슈로 승격하여 "검사했는데 깨끗함"과 "검사 못 함"을 구분___
- ___에이전트 정의 파일 자체의 프롬프트 인젝션 패턴을 점검 대상에 포함___
- ___감사 JSON을 심각도순 색상 코딩 HTML 리포트로 자동 변환하여 스캔 종료 시 즉시 열람___

#### 스캐너 구성

설치 시 3종 스캐너를 자동 설치하며, 이미 있으면 조용히 건너뜁니다.

| 도구 | 역할 | 설치 방식 |
|---|---|---|
| `semgrep` | SAST (정적 취약점) | macOS: brew / Linux: 격리 venv + `~/.local/bin` 심볼릭 링크 (PEP 668 우회) |
| `gitleaks` | 시크릿 탐지 | GitHub 릴리스 바이너리, 아키텍처 자동 판별 (x64/arm64) |
| `trivy` | SCA (의존성 취약점) | GitHub 릴리스 바이너리, SHA256 검증 |

#### scanner-gap — 조용한 스킵 제거

스캐너 자동 설치가 실패했을 때 그냥 넘어가면, 리포트의 "이슈 없음"이 **검사 결과인지 미실행인지** 구분되지 않습니다. 이 경우를 HIGH/MEDIUM 심각도의 `scanner-gap` 이슈로 명시 보고하고, security-auditor는 수동 코드 리뷰로 폴백합니다.

#### 프롬프트 인젝션 점검

에이전트·커맨드 정의 파일(`claude-config` 타입)은 그 자체가 모델에게 주입되는 지시문이므로, 일반 소스코드와 다른 공격면을 가집니다. 정의 파일 내 인젝션 패턴을 별도 점검 항목으로 두었습니다.

#### HTML 리포트 생성

감사 JSON은 `audit-report.js`가 웹 페이지로 변환합니다.

- 심각도 순 정렬 + 색상 배지, `decision_type` 배지 병기
- 이슈별 증거 스니펫 인라인 표시
- security-auditor / code-reviewer 두 루프가 모두 끝난 시점에 1회 생성 후 자동 열람

#### 사용 기술
- semgrep, gitleaks, trivy, Node.js 기반 리포트 제너레이터, 구조화 JSON + Markdown 이중 출력
